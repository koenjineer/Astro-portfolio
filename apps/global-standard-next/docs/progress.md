## 進捗

**サービスページ完了（2026-09-06）**：
実装・共通レイアウト切り出し・SPハンバーガーメニュー・デザインルールセット反映まで完了。

**導入事例ページ完了（2026-09-06）**：`/case`。WPから9社をコース別に取得して表示する。
3コースの「slug / 日本語名 / 英語名」は `lib/courses.ts` に集約し、サービスページと共有する
（サービスページ側の各コースに同じslugのidを振ってあり、アンカーで着地できる）。
カード順はFigmaに合わせて投稿日の昇順（WPGraphQLの既定は降順なのでクエリで `ASC` を指定）。
ロゴ画像は投稿のslugと一致（`logo-aaa.webp` ⇔ slug `aaa`）。
下層ページのヒーローはページごとに写真が変わるため `PageHero` に props で渡し、
見出しはFigmaどおり白い箱の上の紺文字にした（写真の上の白抜きは明るい写真だと読めなかった）。

**お知らせ一覧ページ完了（2026-09-06）**：`/news`。WPの投稿15件を新しい順に1ページ9件で出す。
ページ送りと絞り込みはURLを分ける（`/news/page/2`、`/news/category/<slug>`、
`/news/category/<slug>/page/2`）。4ルートとも `NewsListPage.tsx` を呼ぶだけ。
`generateStaticParams` は**1ページ目も含めて**返す。`output: export` では空配列を返すと
ビルドが止まるため。`/news/page/1` はどこからもリンクしない。
カテゴリの並びと1ページの件数は `lib/news.ts` に集約。WP既定の `uncategorized` はここで弾く。
サムネイルはWPのアイキャッチで管理するが、画像の実体はリポジトリから配る（`docs/wordpress.md`）。

**お知らせ詳細ページ完了（2026-09-06）**：`/news/<slug>` を15件書き出し、一覧とサイドバーの
各行をこのページへのリンクにした。本文はWPが組み立てたHTMLをそのまま流し込み、見た目は
`app/news/_components/entry-content.css` が**タグ名を狙って**当てる
（管理画面で足されるブロックにクラスを付けて回ることはできないため）。
ブロック間は14px、見出しの前だけ30px。引用の飾りの引用符はCSSの背景画像で敷く。
「前の記事」は1つ古い記事、「次の記事」は1つ新しい記事（WordPressの慣例）。
一覧と記事は外枠（ヒーロー・パンくず・2カラム・サイドバー）が同じなので
`NewsPageShell.tsx` にまとめ、寸法を1か所にした。
Figmaのモックは一部の見出しがH4だが、WP側は全部H3で入っている。H2〜H4すべてFigmaどおりの
見た目を用意してあるので、変えたい見出しは管理画面で見出しレベルを変えるだけでよい。

**当社についてページ完了（2026-09-06）**：`/about`。データ連携なし、固定テキストのみ。
MISSIONとVISIONは写真の下辺に白いカードを重ねる同じ形なので `AboutStatement.tsx` を2回呼ぶ。
カードの太字見出しは**改行位置がPCとSPで逆**（MISSIONはSPだけ2行、VISIONはPCだけ2行）なので、
行を配列で渡し、効かせない側の `<br>` を `lg:hidden` / `hidden lg:inline` で消して幅なりに折り返す。
会社概要は `<table>`。項目名の列が値の文字数に引っ張られて縮むため `table-fixed` で幅を固定する。
役員紹介の斜め帯はSVGを貼らず、サービス02と同じ17.57%の傾きの `clip-path` で描く
（画面幅に追従させたいため。高さは「帯の厚み＋17.57vw」）。
SNSアイコンは架空の会社でリンク先が無いので、`aria-hidden` の飾りとして置く（空リンクを作らない）。
画像はFigmaから書き出して `public/images/about/` に置いた（役員写真02・03は元画像が
240×320しかないため等倍。01だけ1.5倍で書き出せている）。

**資料ダウンロードページ完了（2026-09-06）**：`/download` と `/download/thanks`。
データ連携なし、固定テキストのみ。入力ページと完了ページは左カラム（見出し・パンフレット画像・
紹介文）とカード枠が完全に同じなので `DownloadPageShell.tsx` にまとめ、右カラムの中身だけ差し替える。
**フォームは送信しない**（架空の会社のデモなので送信先を作らない）。`onSubmit` で
`preventDefault()` してから完了ページへ移動するだけ。`action` + `method="get"` は
氏名・メールアドレスがURLに残るため使わない。必須3項目とチェックボックスには `required` を付け、
未入力ならブラウザ標準のバリデーションが止める（入力内容はブラウザの外へ一切出ない）。
完了ページの「資料のダウンロードリンクはこちら」と、チェックボックス横の「個人情報保護方針」は
**リンクにせず下線つきの文字だけ**にした（配る資料も方針ページも無いため。
当社についてページのSNSアイコンと同じ判断）。
完了ページのカードはFigmaで左カラムと同じ高さまで伸びているので、2カラムを既定のstretchのままにした。
Figmaの実測でPCとSPが違ったのは、カードの見出し（32px / 24px）・ラベル（18px / 14px）・
必須バッジ（40×20・12px / 36×17・10px）・入力欄の余白（px16 py10 / px14 py12）・
項目間（32px / 20px）・完了カード内の間隔（40px / 34px）。左カラムの見出しは28px/40 と 20px/28。
チェックボックスはFigmaのSVG（枠＋チェック）をチェック時だけ重ね、未チェックは同じ1pxの枠線で描く。

**お問い合わせページ完了（2026-09-06）**：`/contact` と `/contact/thanks`。
資料ダウンロードと同じく**フォームは送信しない**（架空の会社なので送信先を作らない）。
Formspreeは使わない判断にした（外部サービスに入力内容が保存されるのを避けるため）。
資料ダウンロードと違いカード（背景色の箱）が無く、白地に687px幅の1カラムを中央に置くだけなので、
外枠は `ContactPageShell.tsx`、中身は入力／完了で差し替える。
入力欄はFigmaの実測値が資料ダウンロードと全部同じだったので、`FormField.tsx` を
`components/form/` へ移して両ページで共有し、`control` で input / select / textarea を出し分ける。
同意チェックボックスも寸法・文言が同一なので `components/form/AgreementCheckbox.tsx` に切り出した
（チェック済みのSVGは2ページで使うので `public/images/common/` へ移動）。
「ご用件」の選択肢はFigmaに無いので3コース＋その他で作り、コース名は `lib/courses.ts` から取る。
未選択の間だけ文字をplaceholderと同じ灰色にするのは、`required` のselectが未選択だと
`:invalid` になる性質を使ってCSSだけで出し分ける（JavaScriptで状態を持たなくてよい）。
Figmaと違えたのは、textareaを引き伸ばせるようにした点（Figmaに指定が無く、あった方が書きやすい）。

**トップページ完了（2026-09-07）**：`/`。WPGraphQL疎通確認の仮ページを差し替えた。
導入事例は投稿日の昇順で先頭6件（`getCaseItems()`）、お知らせは最新3件。
仕様書は「最新の6件」だが9件とも投稿日が同じで新旧を決められないため、Figmaのモックと
`/case` の並びに揃えて先頭から取る（ユーザーと合意）。カードは `/case#<slug>` へ送り、
着地点として `CaseCard` に `id` を足した（事例に詳細ページが無いので一覧の該当社へ飛ばす）。
ファーストビューは3枚のクロスフェード（6秒ごとに1秒かけて切り替わる）。Swiper等は入れず
`setInterval` と `transition-opacity` だけで作る（「視差効果を減らす」設定なら
1枚目のまま切り替えない）。**1枚前の写真は不透明のまま下に敷いたままにする**。
3枚を同時に薄くすると下地の白が透けて、切り替わりの一瞬だけ写真が白っぽく飛ぶため
（実機で確認して直した。重ね順を枠の中だけで解決させるため親に `isolate` を付けている）。
見出し（`SectionHeading`）とView moreリンク（`ViewMoreLink`）はトップでしか使わないので
`app/_components/` に置いた。
View moreの丸・線・矢先はSVGを貼らず3要素で描く。ホバーで線だけを伸ばすため。
PCではView moreが見出しの右、SPではセクション末尾に来るが、同じリンクを2つ作らないよう
DOMは1つのままCSSで位置を変えている。
薄青の斜め帯3本は当社についてページと同じ17.57%の `clip-path`
（SPのお知らせだけFigmaは15.5%だが、実差8pxなので1つの定数に揃えた）。
サービスのコース名は**Figmaがページごとに違う**（トップは「異文化コミュニケーション研修」
「ビジネス留学サポートプログラム」、サービスページは「異文化コミュニケーション」
「ビジネス留学プログラム」）。デザインどおりに分けてあるので、`lib/courses.ts` に
寄せ直さないこと。トップのコース名は `HomeService.tsx` の固定テキスト。
Figmaと違えたのはお知らせの見出しだけ（SPだけ「新着情報」だが「お知らせ」に統一）。
画像は `public/images/home/` にFigmaから6枚書き出した（about / about-bg / case-bg のPC・SP）。
サービスの番号（01〜03）はFigmaでは写真の手前に重なるので `z-10` を付ける
（付けないとDOM順で後に来る写真に隠れる）。

トップページの実装にあわせて共通ヘッダー（`components/layout/SiteHeader.tsx`）も
Figmaに合わせた：ナビ項目のあいだに「／」を入れ（前後16px・飾りなので `aria-hidden`）、
ナビとボタンの間を30px、資料ダウンロードとお問い合わせの間を10px空けた。全ページに効く。

全8ページの実装が完了。以降は共通部品を触った時にまとめて確認する。
