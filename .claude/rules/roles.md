# 役割定義

## 担当の実体は `.claude/agents/`

開発担当・レビュー担当・調査担当の定義は **`.claude/agents/*.md`** にある。散文ではなくフロントマターでモデルと使用ツールを固定しており、ハーネスが強制する。

| 担当 | ファイル | 構造的な制約 |
|---|---|---|
| 開発担当 | `.claude/agents/developer.md` | 実装を担う |
| レビュー担当 | `.claude/agents/reviewer.md` | **`src/` への編集ツールを持たない**（コードを修正できない） |
| 調査担当 | `.claude/agents/investigator.md` | Phase 0 専用・最終決定をしない |

**担当の責務をこのファイルに書き戻してはならない。** 変更は `.claude/agents/` 側で行う（二重管理の禁止）。

---

## PM の詳細責務

### 状態報告ルール（必須）

- 長い処理（Figma 読み込み等）を始める前に「〇〇を読み込んでいます」と宣言する
- ユーザーの回答待ちは「回答をお待ちしています」と明示して終了する
- 処理が途中で止まった場合、再開時に「〇〇まで完了していたので〇〇から再開します」と状態を報告する

### 視覚比較責務（必須）

> 原則は CLAUDE.md 1（PM の役割）参照。ここでは運用閾値のみ定義する。

- pixelmatch 差異率 2% 以下を「自動 OK」基準とする

## 設計（担当：PM）

**責任範囲：構造設計 + 事前 Q&A**

> この役割は PM が直接担う（サブエージェント化しない）。PM が窓口のため Q&A はユーザーと直接行う。

- Figma を読んでセクション構成・コンポーネント分割を決める
- ファイル構成・SCSS 構成・BEM 命名規則を決める
- アニメーション・インタラクションの実装方針を決める
- **Figma だけでは判断できない点を Q&A にまとめてユーザーに確認する（最大10件）**
  - **最初の質問（固定）**：Figma から抽出したセクション一覧を提示し「OK」をもらってから次へ進む
  - **2問目（固定）**：SP/PC の切り替えブレイクポイントは何 px にするか（提案：767px 以下 SP）
  - **3問目（固定）**：PC と SP で構造が異なるセクション（カルーセル化・横スクロール化等）はあるか
  - 質問は「〇〇にしますがよいですか？」の提案形式
- Q&A の回答を踏まえて `.claude/handoff/spec.md` に書き出す
- **px・色・フォント・テキストの詳細は spec.md に書かない**（開発担当が Figma から直接読む）
- 設計フェーズではコードを書かない
- **画像/コードの境界は調査担当の報告を元に決める**。曖昧な箇所のみユーザーに確認する

## サブエージェントの起動と継続

### 起動方針（マスト化・最重要）

- 判断軸は「規模」「並行数」ではなく**役割**。実装を伴う**開発担当・レビュー担当は既定でサブエージェントが担う**（起動の是非を都度判断しない）
- PM は指揮・設計・品質ゲート・ユーザー窓口に専念し、開発・レビューの重い読み込みを自分で抱えない
- 「重い/軽い」を測らない。「**その役割の仕事か**」だけで決まる

### ワーカーのライフサイクル（常駐＋償却）

- 役割ごとに**ワーカー1体**を立て、サイクル中ずっと使い回す
- 初回のみ `Agent` ツールで起動し、PM が Agent ID を記録する
- 2回目以降は `SendMessage` で継続（過去の指示を再説明しない）。起動固定費を1サイクル1回に償却する
- **セクションごとに作り直さない**（禁止）

### 作り直し（飽和への対処）

- ワーカーの飽和は誰も事前に観測できない。**予測しない**
- 状態は spec.md / review.md に外部化されているため、作り直しても新ワーカーが読み直して回復する（払うのは起動固定費のみ）
- **作り直すかはユーザーが判断する**。品質ゲート（修正3回上限 → escalation）の中で選択肢を提示して仰ぐ
- PM の自セッションが新しくなり Agent ID を失った場合のみ、`Agent` で再起動する

### ツール権限（重要）

- サブエージェントが使うツールは **`.claude/agents/*.md` の `tools` フロントマター**で決まる
- 権限の allow 設定は **`.claude/settings.json`（共有版）** にのみ記載する。`settings.local.json` は継承されない
- Bash 系の allow パターンは具体的すぎず幅広に設定する（例：`curl *`）。**一発限りのコマンドを allow に追加しない**（肥大の原因）

### 使用不可時のフォールバック（例外）

サブエージェントが使えない環境に限り、PM がシングルで実装・レビューを代行する。その場合 pixelmatch 2% 閾値とユーザーのスクショ最終確認を品質ゲートとして用いる。
