# 2026-09-15 共通部分＋お問い合わせ（ブランチ `feat/open-cafe-contact`）

ルールセットの色・フォント、下層ページ上部（写真＋二重線＋メニューボタン）、ドロワーメニュー、パンくず、
フッター（吹き出し・地図画像・店舗情報・パンと豆の飾り・SNS）、ページトップへ戻る、デフォルトボタン、
お問い合わせ入力／完了を作った。仮ページ `app/page.tsx` は残し、共通フッターが載っても表示が崩れないことを確認。

計画から変えたこと・決めたこと：

- **フォントの太さはNoto Serif JP Medium(500)/Bold(700)**。計画は Regular/Bold だったが、ルールセットの指定がMedium/Bold
- **Damionは読み込むが先読みしない**（`preload: false`）。今回のページでは使っておらず、先読みすると全ページで読み込まれるため
- **色の名前**：Figmaの cr-base(#F3EFEB) は `base-light`、cr-base-dark は `base-dark`。`--color-base` は文字サイズの `text-base` と衝突するため（`/rules/tailwind.md`）
- **SNSアイコンはリンクにしない**。架空のカフェでリンク先が無いので、global-standard-next と同じく飾り（`aria-hidden`）として置いた。南歯科にはSNSが無い
- **吹き出しは画像だがaltを付けた**（「吉祥寺駅から徒歩5分！」という情報を持つため）。SVGはPC・SPで同じ形なので1枚にした
- **地図は1倍で書き出した**。元の画像が669×367しかなく、1.5倍にすると引き伸ばしになるため。文字の絵なので可逆webp
- **お問い合わせ項目のラジオは先頭「お店のご利用・ご予約について」を選んだ状態で始める**（Figmaどおり。ユーザー決定）。`required` は残す
- **メニューボタンは画面の右上に固定**（ユーザー決定）。写真の上では Figma と同じ右上10pxに見え、スクロールしても押せる。
  外枠を `fixed` にすると中のドロワーがその重なり順に閉じ込められるので、外枠を z-50（ページトップへ戻るの z-40 より上）にした
- **フォームの送信は `<form action={関数}>`**。`onSubmit` + `preventDefault` だと、JS起動前に押すと標準のGET送信で入力内容がURLに出るため（`/rules/nextjs-static-export.md`）
- **行の高さは文字サイズと一緒に書く**（`text-xs/[1.5]`）。親の `leading-[1.5]` は子の `text-xs` 等に打ち消されていた（`/rules/tailwind.md`）。見出しの日本語・ドロワーの項目・コピーライトを直した
- **読み上げの区切り**：見出しとドロワーの項目は、英字と日本語の間に見えない読点（`sr-only`）を入れ、「access、アクセス」「top、トップ」と読ませる
- **ハイコントラスト表示**：ラジオの選択の点は `forced-colors:bg-[CanvasText]` と `forced-color-adjust-none` で消えないようにした
- **ページトップへ戻るは画面に追従**させた（Figmaはフッター右下に固定）。南歯科と同じ判断。写真(320px)を過ぎたら出す
- **ドロワーの開閉は右へのスライド300ms**。Figmaに動きの指定は無い。動きを減らす設定では付けない
- **ドロワーは `<dialog>` を使わず、ドロワー以外を inert にする**。写真の中（本文側）に置いたので、ドロワーから body までの各階層の兄弟に付ける（`components/layout/drawerMenuInert.ts`）
- **開くときに visibility を遅らせない**。遅らせると開いた直後の1フレームは hidden 扱いで、閉じるボタンへのフォーカスが効かなかった（実機で発見）
- **`<html>` に `scrollbar-gutter: stable`**。ドロワーを開くとスクロールを止めてスクロールバーが消え、裏のページが約7px横にずれたため
- **フッターの地図の縦横比は白枠を含む箱で持つ**。width/height属性だけだと中身に比率がかかり、枠の分だけ9px背が高くなった
- **フッターの店舗情報のPC2列は `grid-rows-[repeat(3,auto)]`**。`grid-rows-3` だと行の高さがそろって45px高くなった

### タブレット幅（768〜1023px）の実測

PCの組みに切り替える幅を **`md`（768px）** にした。実機Chromeで768px（clientWidth 768）を測った値：

- 本文の枠は688px（768−左右20px×2＝728pxに収まる）。案内文は1行688pxで、PCと同じ長さ
- フォームはラベル列170px＋入力欄490px。PCと同じ寸法で、横はみ出し無し（scrollWidth 768）
- フッターのパン（右上の飾り）と「ACCESS」の文字の間は **6px** 空く（1280pxでは約260px）。重ならないので、パンはPCの大きさのまま
- 吹き出しは左端から80px、地図の上端（1902px）はパンの下端（1873px）より下
- SPの組みのまま768pxに伸ばすと、入力欄が728px幅まで伸びて1行が長くなるため採らなかった

**2026-09-16 追記：フッター左下の豆が店舗情報の文字に重なっていた**（768pxで TEL・Mail が読めなかった）。

- 原因：768px以上で豆をPCの大きさ（左−66px・幅322px・高さ289px、フッター上端から705px）で置いていた。
  本文の左端は「(画面幅−688)/2」なので、豆の右端256pxより本文が右に来る**画面幅約1200px以上**でないと、
  豆が店舗情報の左列（フッター上端から636〜778px）にかかる
- 判断：**768〜1279pxだけ豆を幅231px（高さ207px）・左−47pxに縮める**（はみ出し量も幅と同じ比率）。
  上端がフッター上端から787pxになり、店舗情報の最後の下線（778px）より下に来るので、本文の位置に関係なく文字にかからない。
  文字より奥に置く案は、豆も文字も濃い茶色で読めなくなるので採らなかった。1280px以上（`xl`）と375pxはFigmaのまま
- 実測（実機Chrome、同一オリジンのiframeで中身の幅を合わせ、画像の読み込み完了を確かめてから測った）：

| 中身の幅 | 豆（左・幅） | 豆と文字の重なり | 豆の上端と表の最後の文字の間 | パンと「ACCESS」の文字の間 |
|---|---|---|---|---|
| 375 | −29・121（Figma） | なし | 26px | −16px（Figmaと同じ位置で角がかかる） |
| 768 | −47・231 | なし | 16px | 6px |
| 820 / 900 / 1000 | −47・231 | なし | 16px | 32 / 72 / 122px |
| 1024 / 1100 / 1200 | −47・231 | なし | 16px | 134 / 172 / 222px |
| 1279 | −66・322（Figma） | なし | ―（本文の左端295pxが豆の右端より右） | 261px |
| 1280 / 1455 | −66・322（Figma） | なし | ― | 262 / 349px |

- 1279pxでFigmaの大きさになるのは、`xl`（1280px）の判定がスクロールバーを含む画面幅で行われるため。
  このときも本文の左端（295px）が豆の右端（256px）より右なので重ならない
- パンは768px以上で「ACCESS／アクセス」の文字にかからない（768pxで6px、幅が広いほど離れる）。
  メニューボタン（画面右上に固定）はスクロールするとどの幅でもパンの上に重なるが、ボタンが一番上にあり押せる

- **フッターの店舗情報の下余白は5px**（Figmaは6px）。Figmaの下線は内側の線で高さを増やさないが、CSSの border は1px足すため。
  6pxのままだと1行ごとに1px高くなり、フッターがPCで3px・SPで6px高かった

- フッターの高さ：PC 994px・SP 932px（Figmaと一致。修正前は 996px / 936px）
