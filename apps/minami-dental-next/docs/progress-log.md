## 2026-09-11 お知らせ（ブランチ `feat/minami-news`）

- ブログでも使う部品を `components/archive/` に置いた（外枠・カード・カテゴリ札・サイドバー・ページ送り・前後の記事ボタン・
  記事の本体・本文のCSS）。記事・カテゴリー・URLの作り方は引数（`types.ts` の `ArchiveRoutes`）で受け取る。
  お知らせ専用は `app/news/_components/`（一覧の組み立て `NewsListPage.tsx`、URLと見出し `newsConfig.ts`）
- `PageHero` に見出しをh1にしない指定（`titleAs`）を足した。詳細ページは記事名がh1になるため。既存ページの見た目・出力は変わらない
- アイコン：ペン・丸矢印は `SmallIcons.tsx`、サイドバーの見出しのアイコンと矢印は `SidebarIcons.tsx`（1ファイルだと200行を超えるため分けた）
- 素材：代わりのサムネイル `public/images/news/thumb-fallback.webp`（600×315）、
  診察室の写真 `public/images/archive/sidebar-clinic.webp`（670×447、元1920×1280）。どちらも `cwebp -q 90`
- `lint`・`build` が通り、書き出しに `minami-dental-cms.local` が残らないこと、詳細ページのh1が1つであることを確認

判断したこと：

- 1ページ9件（`NEWS_PER_PAGE`）、サイドバーの新着記事4件、カテゴリーの並びは TERM_ID 昇順（詳細は `docs/wordpress.md`）
- 代わりのサムネイルはFigmaでは画像（1200×630）だったので、SVGにせずwebpにした
- 「次の記事へ」はFigmaの部品置き場にも無い（ページ送りの「次へ」だけ）。「前の記事へ」と対になる形（塗り＋右向きの丸矢印）で作った。
  Figmaのボタン列の幅（PC 352px / SP 324px）が3つ並べた幅と一致するので、「記事一覧」が常に真ん中に来るよう左右を同じ幅の列にした
- ページ送り・前後の記事ボタン・サイドバーのリンクはFigmaにホバーが無いので、サイト共通の約束に合わせた（`docs/design-rules.md`）
- 記事の本体（見出し・日付・本文・ボタン）もブログと同じ作りなので `components/archive/ArchiveArticle.tsx` にした（プランの表に無い部品）
- 本文の空の段落は `p:empty` で消し、ブロックの間隔は gap で取った（消した段落のぶん間隔が二重にならない）
- サイドバーの説明文の「貢献しきたい」はFigmaの誤字なので、サイト側だけ「貢献していきたい」に直した（ユーザー決定。Figmaは直さない）
- 一覧4ルートの「記事とカテゴリーの取得→カテゴリーの確認→ページ分け→無ければ404」は `NewsListPage` の中の1か所にまとめ、
  各ルートはページ番号とカテゴリーのslugを渡すだけにした。記事1件の取得（`getNewsPost`）は React の `cache()` で包み、
  詳細ページの `<title>` 用と本体で2回取りに行かないようにした

  知らないタイプが増えたらビルドが止まる）
- フッターのサイトマップ「診療内容」の8項目を各カードへ付け替えた
- 本文の幅の枠 `ContentWidth` を2ページ目で使うので `components/layout/` へ移した
- WPの01〜03の説明文（別の診療の文が入っていた）を、ユーザーが管理画面でFigmaの文章に直した

判断したこと：

- 波は画面幅に合わせて比率を保って伸縮する（1280pxより広い画面でも波が切れない）。下の波を帯に重ねる量と、
  SPの帯の下の余白は画面幅に対する%で持ち、どの幅でも最後のカードに波が食い込まないようにした（レビュー指摘）
- 波が小数のピクセルの高さになり帯とのつなぎ目に細い線が出たので、1pxずつ重ねて消した（実機Chromeで発見）
- 1列表示（1024px未満）のカードの写真は、元の写真（630px）より引き伸ばさないよう630pxで止めた
- 白文字と `main`・`accent` の地の組み合わせは文字の見やすさの基準（WCAG AA 4.5:1）に届かない（約3.3〜3.4:1）が、
  Figmaの色の決まりどおりにした
